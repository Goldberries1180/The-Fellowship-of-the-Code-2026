## Summary
After visualising the structure and appearance of the application in Chapter III, this phase focused on transforming static screens into an interactive experience through JavaScript.

The goal was no longer only to represent information visually, but to create behaviour, interaction, and responsiveness within the application. Buttons, navigation, dynamic elements, and hidden features became functional through collaborative experimentation and iterative testing.
Unlike the previous HTML / CSS phase, this stage was approached in a hackathon-style setting. Instead of parallel work on separate screens, the group worked together around a single notebook. One person implemented the code while the others discussed logic, proposed solutions, and reviewed functionality in real time.

This created a highly collaborative atmosphere where ideas could immediately be tested, challenged, and improved.

**Learning Outcomes**

Interactive development benefits strongly from shared discussion and immediate feedback. Writing JavaScript together as a group improved understanding of logic, flow, and behaviour much more effectively than isolated implementation work.

We also learned that rapid prototyping combined with continuous testing leads to faster iteration cycles and earlier discovery of usability and implementation issues.

### AI Assistance

AI was used as a technical assistant during implementation and debugging. It supported the group during logic creation, syntax formulation, and troubleshooting while the team remained responsible for all architectural and creative decisions.

**What did we expect?**

To use AI primarily as a programming assistant for JavaScript methods, debugging support, and technical problem solving during implementation.

**What actually happened?**

AI assisted during:
- Formulating JavaScript methods and event logic
- Debugging application behaviour and runtime issues
- Supporting rapid experimentation during the hackathon workflow
- Identifying possible causes for unexpected application behaviour

**How did AI help or mislead us?**

**Helpful**
- Accelerated debugging and reduced research time
- Helped formulate methods and interaction logic faster
- Allowed quicker experimentation with alternative solutions
- Supported collaborative discussions by providing immediate technical input

**Misleading**
- Occasionally proposed solutions that were technically correct but unnecessarily complex
- Did not always fully understand the project structure or existing logic dependencies
- Some generated fixes solved symptoms rather than root causes

**What decisions did we make consciously?**
- All final implementation decisions remained within the team
- The group discussed and validated AI suggestions before implementation
- Testing was always performed manually after each implemented feature
- The hackathon workflow was intentionally maintained throughout the development process

**What would we do differently next time?**  
We occasionally lost focus by following too many spontaneous ideas during development. While many of those features were technically interesting and motivating, they sometimes distracted us from the original project scope. In future iterations, we would define clearer goals and explicit non-goals at the beginning of the project and regularly revisit the original requirements to reduce scope creep and maintain focus during implementation.

## Lessons Learned

  **Insights**
- Collaborative live-coding encouraged faster idea exchange and stronger team involvement
- Working together on one notebook created more alignment than isolated parallel programming
- Immediate testing after each feature significantly reduced later debugging complexity
- JavaScript development exposed interaction problems that were invisible in static prototypes
- Hidden features and playful elements increased team motivation and creativity during development

**Challenges**  
- Coordinating many ideas simultaneously during collaborative coding
- Maintaining structure while working in rapid hackathon cycles
- Avoiding spontaneous “quick fixes” that could later reduce maintainability
- Balancing experimentation with stable implementation

**Reflections**  
The hackathon-style workflow proved to be highly motivating and productive for interactive development tasks. Compared to the earlier parallel HTML implementation phase, the collaborative setup around a single device created more discussion, stronger shared understanding, and faster problem solving.

AI worked best as an active technical companion during implementation and debugging, especially in situations where fast iteration was required. However, critical thinking and team discussion remained essential to evaluate whether suggested solutions truly fit the project architecture.

One of the most memorable aspects of this phase was the inclusion of a hidden easter egg within the application — a small detail that reflects the playful and experimental spirit of the project and waits to be discovered.
